# 코드 리팩토링 가이드라인

이 문서는 코드의 유지보수성, 가독성, 재사용성을 향상시키기 위한 리팩토링 가이드라인을 정의합니다. 모든 코드는 명시된 세 가지 범주 중 하나에 속하도록 구성해야 합니다.

## 1. 공통 코드 (Common Code)

공통 코드는 여러 프로젝트에서 재사용될 수 있는 범용적인 모듈입니다.

**특징**: 특정 도메인에 종속되지 않는 순수한 기능(Utility)을 제공합니다. (예: 날짜 변환, 파일 처리, 데이터 암호화 등)

**위치**: `src/common/` 디렉토리 하위에 위치시켜 다른 프로젝트에서 쉽게 가져다 쓸 수 있도록 관리합니다.

**리팩토링 목표**: 최대한 일반적이고 독립적으로 만들어 의존성을 최소화하고 재사용성을 극대화합니다.

## 2. 특화 코드 (Specialized Code)

특화 코드는 현재 프로젝트의 특정 도메인 로직을 처리하는 코드입니다.

**특징**: 프로젝트의 고유한 요구사항과 비즈니스 규칙을 구현합니다. (예: 특정 서비스의 사용자 인증, 상품 데이터 처리, 주문 로직 등)

**위치**: `src/` 디렉토리 직하에 위치시켜 프로젝트의 핵심 도메인 로직을 명확히 구분합니다. 공통 코드와 분리하여 관리합니다.

**리팩토링 목표**: 도메인 개념이 명확하게 드러나도록 함수와 클래스 이름을 구체적으로 작성하고, 관련된 로직끼리 응집도 높게 구성합니다. 프로젝트 코드에서 분리된 복잡한 로직들이 이 범주로 이동해야 합니다.

## 3. 프로젝트 코드 (Project Code)

프로젝트 코드는 공통 코드와 특화 코드를 조합하여 애플리케이션의 핵심 흐름을 구성하는 진입점(Entry Point) 역할을 합니다.

### 핵심 원칙:

1. **단일 책임 함수**: 프로젝트의 핵심 로직은 단 하나의 메인 함수에서 시작되어야 합니다. 이 함수가 전체 워크플로우를 조율(Orchestration)하는 중심점입니다.

2. **방사형 호출 구조**: 함수 호출 그래프는 이 메인 함수를 중심으로 하는 방사형(Star-shaped) 구조를 가져야 합니다. 즉, 메인 함수가 여러 특화 함수들을 호출하지만, 특화 함수 간의 복잡한 호출은 지양합니다.

3. **최상의 가독성**: 메인 함수는 한눈에 전체 로직의 흐름을 파악할 수 있도록 작성되어야 합니다.
   - 복잡한 분기, 반복, 세부 구현은 **특화 코드(2번 범주)**로 분리하고, 메인 함수에는 잘 명명된 함수 호출만 남겨둡니다.
   - 메인 함수를 읽는 것만으로 "무엇을(What)" 하는지 명확히 알 수 있어야 하며, "어떻게(How)" 하는지는 특화 코드가 담당하도록 위임합니다.

### 리팩토링 목표:

- **핵심 로직 집중**: 메인 함수가 프로젝트의 핵심 시나리오를 명확하게 보여주는 '목차'처럼 기능하도록 만듭니다.
- **추상화**: 세부 구현 로직을 특화 코드로 옮겨 메인 함수를 깔끔하고 간결하게 유지합니다. 함수의 이름만으로 어떤 동작을 하는지 쉽게 예측할 수 있어야 합니다.

## 테스트 전략

### Phase 1, 2, 3: 기능 테스트 중심
- **pytest만 실행**: 기능이 올바르게 동작하는지 확인하는 데 집중
- **커밋 기준**: pytest가 통과하면 즉시 커밋하여 작업 내용 보존
- **목표**: 리팩토링 과정에서 기능이 변경되지 않았음을 보장

### Phase 4: 코드 품질 검사
- **코드 포맷팅**: black으로 일관된 코드 스타일 적용
- **스타일 검사**: flake8 또는 ruff로 코드 스타일 가이드 준수 확인
- **타입 검사**: mypy로 타입 힌트 일관성 검증
- **최종 커밋**: 모든 검사 통과 후 코드 품질 개선 사항 커밋

이러한 단계적 접근을 통해 기능 안정성을 먼저 확보한 후, 코드 품질을 개선합니다.

## 리팩토링 시 테스트 코드 관리

리팩토링으로 함수가 다른 모듈로 이동하면, 해당 함수의 테스트도 함께 이동해야 합니다.

- **원칙**: 함수와 테스트는 항상 대응하는 모듈에 위치
  - `src/module.py` → `tests/test_module.py`
- **예외**: main 함수의 통합 테스트는 원래 위치 유지

### 중복 테스트 제거

단순한 래퍼 함수의 경우 중복 테스트를 피해야 합니다.

- **래퍼 함수**: 다른 모듈의 함수를 단순히 호출하는 함수
  - 예: `setup_korean_font()` → `korean_font_utils.setup_korean_font()` 호출
- **처리 방침**: 
  - 원본 함수가 이미 테스트된 경우, 래퍼 함수는 별도로 테스트하지 않음
  - 필요시 통합 테스트에서 mock으로 처리
  - DRY 원칙에 따라 중복 테스트 방지
